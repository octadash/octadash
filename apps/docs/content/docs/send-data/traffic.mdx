No cookies and, by default, no consent banner needed. The script is under
2.5 KB, follows client-side navigation in single-page apps and skips visits
from `localhost`. The same script also reports the page's uncaught errors
(Errors) and sends `track` events (Product usage), so you install it once per
source.

## Several sites in one product

The site, the docs and the app of one product are separate sources, each with
its own script. In Traffic, **Add source** gives a new one its name and code.
The page adds them up, and the **Sources** card shows each one: click a source
to see only its numbers.

## Options

- `data-visitor="persistent"`: the browser keeps a random id, so a returning
  visitor counts once. Off by default; turning it on is your choice, consent
  included where the law asks for it. Set it per source in the panel.
- `data-local`: counts visits from `localhost`, for testing.

## What is stored

Path, referrer, UTM tags, browser, system, device and country. The visitor's
address is never stored: a visitor id is a hash of a salt of the day, the
product, the address and the browser, and once the salt expires no one can link
two days. Bots are kept and shown apart.

The country comes from a header your proxy adds (Cloudflare, CloudFront,
Vercel). Without one it stays empty.

Page views are kept 13 months by default, so this month can be compared with
the same month last year; 3, 6 or 25 months in **Product settings** > **Data
kept** (one choice for Traffic and Product usage). A shorter choice deletes
what is older right away.

Already on PostHog? Its web SDK sends `$pageview` with the same names, so it
fills Traffic too. See [Coming from PostHog](/send-data/migrate#posthog).
