title: Assistentes de IA (MCP)
description: Deixe o Claude, o Cursor ou qualquer assistente que fale MCP trabalhar com seus produtos, com um token que permite só o que você escolher.
---

O Octadash serve um servidor [Model Context Protocol](https://modelcontextprotocol.io)
em `/api/mcp`, no endereço do painel. Um assistente conectado a ele trabalha com
os produtos de uma organização: só vê as ferramentas que o token permite, e você
responde pelo que ele faz com elas.

## Crie um token

1. Em **Configurações do Octadash** (rodapé do menu lateral) > **Tokens de API**, clique em
   **Novo token** e dê a ele um nome que diga onde ele é usado ("Claude no meu notebook"). Donos e
   admins podem fazer isso.
2. Escolha o que ele pode tocar. Comece de um preset e mude qualquer item:

   | Preset        | O que permite                                                         |
   | ------------- | --------------------------------------------------------------------- |
   | Só leitura    | Lê todos os itens. Não muda nada.                                     |
   | Setup com IA  | Lê todos os itens e escreve produtos e origens, para a [skill de setup](/pt/use/install-with-ai) colocar o Octadash em um projeto. |

   Cada item (produtos, origens, chaves, monitores, alertas, tráfego, uso do
   produto, eventos-chave, erros, logs, dinheiro, custos, configurações) fica em
   **Sem acesso**, **Leitura** ou **Escrita**; escrita inclui leitura.
   **Apagar** é uma permissão à parte, desligada por padrão e só onde o token
   pode escrever. Um item ainda sem ferramenta guarda a escolha para quando elas
   chegarem.
3. Copie o token agora: ele aparece uma vez só. O Octadash guarda apenas um hash
   dele.
4. Revogue na mesma página quando aquele assistente deve parar. Um token alcança
   todos os produtos da organização, dentro dos itens dele.

## Conecte um assistente

Depois de **Criar token**, a janela mostra como conectar, pensando também em
quem nunca abre um terminal:

- **Copiar mensagem para a IA**: uma mensagem para colar em qualquer chat de
  IA. Ela diz o que é o Octadash, leva o endereço e o token, e pede ao
  assistente que conecte sozinho (quando ele roda comandos) ou guie você no seu
  app, um passo por vez.
- Uma aba por app com passos simples: Claude (site, computador e celular),
  ChatGPT, Cursor e VS Code (botões de um clique) e o terminal (Claude Code).

### Claude e ChatGPT

Os conectores personalizados deles aceitam só um endereço, então usam o
endereço com o token embutido: `https://octadash.example.com/api/mcp/oct_...`.

- **Claude**: Personalizar > Conectores > + Adicionar > Adicionar conector
  personalizado. Nome Octadash, cole o endereço com token, Autenticação "Sem
  login". Nos planos Team e Enterprise quem adiciona é o dono da organização. O
  Claude conecta a partir dos servidores da Anthropic, então seu Octadash
  precisa responder pela internet na porta 443.
- **ChatGPT**: Configurações > Apps > Configurações avançadas > Modo
  desenvolvedor ligado, depois Criar app com o endereço com token e Sem
  autenticação.

Trate o endereço com token como o próprio token: quem tiver usa o Octadash com
as permissões dele. Revogue o token se vazar.

### Clientes que enviam cabeçalho

No Claude Code, com o comando que a janela mostra:

```sh
claude mcp add --transport http octadash https://octadash.example.com/api/mcp \
  --header "Authorization: Bearer oct_..."
```

Cursor, VS Code e outros clientes: o servidor fala Streamable HTTP (respostas em
JSON, sem sessão) e recebe o token como `Authorization: Bearer <token>`.

```json
{
  "mcpServers": {
    "octadash": {
      "type": "http",
      "url": "https://octadash.example.com/api/mcp",
      "headers": { "Authorization": "Bearer oct_..." }
    }
  }
}
```

## Ferramentas

As ferramentas de leitura aceitam um produto opcional (o slug ou o nome); sem
ele, respondem por todos os produtos. Os itens do token decidem quais
ferramentas o assistente vê.

| Ferramenta         | Precisa | Responde                                                                                    |
| ------------------ | ------- | ------------------------------------------------------------------------------------------- |
| `list_products`    | Produtos: leitura | Os produtos (slug e nome) e os grupos salvos.                                                         |
| `uptime_status`    | Monitores: leitura | Cada monitor: estado agora, disponibilidade e tempo de resposta mediano em 24 horas e 30 dias, dias restantes do certificado. |
| `open_emergencies` | Alertas: leitura | O que está aberto agora: emergências e sinais, desde quando e se alguém está cuidando.                |
| `traffic`          | Tráfego: leitura | Visitantes e páginas vistas nos últimos dias (7 por padrão, até 90) contra os dias anteriores, com as principais páginas, origens, canais e países. |
| `search_logs`      | Logs: leitura | Linhas de log, das mais novas, com a mesma busca da página Logs (`level:error timeout`), até 7 dias atrás. |
| `list_sources`     | Origens: leitura | As origens de um produto, as áreas que cada uma alimenta e quando cada uma enviou por último uma página vista, um evento, um erro ou uma linha de log. |
| `source_setup`     | Origens e chaves: leitura | A chave pública, o DSN e o código exato de instalação de uma origem por área, o mesmo código do painel. |
| `create_product`   | Produtos: escrita | Cria um produto pelo nome, ou devolve o que já tem esse nome. |
| `create_source`    | Origens: escrita | Adiciona uma origem a um produto, ou devolve a que já tem esse nome. |

As ferramentas que escrevem só adicionam; renomear, trocar chave e apagar
continuam no painel. Cada área ganha as próprias ferramentas quando fica pronta. Perguntas que
funcionam bem: "está tudo no ar?", "o que está aberto agora?", "como foi o
tráfego desta semana contra a anterior?", "mostre os erros nos logs da API da
última hora".

Dados pessoais nos logs já foram mascarados quando a linha chegou, então o
assistente nunca os vê.
