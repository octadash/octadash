---
title: Como atualizar
description: Como saber que existe versão nova e como instalar no Coolify ou no Docker Compose.
---

Toda mudança que entra no Octadash publica uma imagem nova,
`ghcr.io/octadash/octadash:edge`. Atualizar é baixar essa imagem e recriar os
containers. Cada papel aplica as migrações pendentes ao iniciar, no Postgres e
no ClickHouse, então não há nada para rodar à mão. Os seus dados ficam nos
volumes.

## Saber que existe uma

O menu mostra a versão em uso embaixo do nome: `v1.4.0` para uma versão
publicada, `edge · 4752944` para uma imagem gerada do `main` (o commit de onde
veio). `/api/health` também informa.

Uma vez por dia o painel pergunta ao GitHub se há versão nova. Quando há, donos
e admins veem **Atualização disponível** no menu, acima de Configurações, com
link para o changelog. Uma imagem de versão compara com a última versão
publicada; uma imagem `edge` conta as mudanças no `main` desde que foi gerada.
Com `OCTADASH_UPDATE_CHECK=false` o painel nunca chama o GitHub.

O que mudou está no [changelog](https://octadash.com/changelog/).

## Coolify

1. Abra o recurso do Octadash.
2. Clique em **Redeploy**.

Só isso. No redeploy, o Coolify busca o arquivo compose mais recente do
repositório, baixa as imagens de todos os serviços (inclusive a `edge`, mesmo
com a mesma tag), para os containers antigos e sobe os novos. Nenhuma variável
de ambiente precisa mudar, a não ser que o changelog diga. O painel e o ingest
ficam fora do ar por alguns segundos enquanto os containers reiniciam; os SDKs
e o script tentam de novo o que falhar no envio.

## Docker Compose

Na pasta onde o Octadash roda:

```bash
git pull
docker compose pull
docker compose up -d
```

`git pull` traz o arquivo compose da versão nova, `docker compose pull` baixa a
imagem nova (um `up -d` sozinho mantém a imagem que já tem com a mesma tag) e
`up -d` recria só o que mudou.

Instalou com o [comando único](/pt/install)? Rodar de novo faz o mesmo: atualiza a
cópia, mantém as senhas e baixa a imagem nova.

## Ficar em uma versão

Os arquivos compose usam `OCTADASH_VERSION`, `edge` por padrão. Quando houver
versões publicadas, defina `OCTADASH_VERSION=1.2.0` (no `.env` ou nas variáveis
de ambiente do Coolify) para ficar nessa versão e só mudar quando você trocar.
As versões de ClickHouse, Valkey e Garage ficam fixas nos arquivos compose e só
mudam com o Octadash.

## Vindo de uma versão sem armazenamento de arquivos

Atualize o repositório, rode `./scripts/generate-env.sh` de novo (ele adiciona
`GARAGE_RPC_SECRET`, `STORAGE_ACCESS_KEY_ID` e `STORAGE_SECRET_ACCESS_KEY` ao
seu `.env` e mantém o resto) e depois `docker compose up -d`.
